## 1. 产品概述

### 1.1 背景与问题

卫星遥感是森林砍伐监测、水体污染追踪、作物长势评估等工作的核心手段，大量科研人员、环保监测工程师与农业分析师依赖 Google Earth Engine（GEE）开展影像分析。但：

- **GEE 需要编程基础**：遥感分析代码编写复杂、调试耗时，频繁试错严重拉低效率；
- **学习曲线陡峭**：生态学家、基层环保工作者等非技术用户难以直接上手，被迫依赖专业编程人员；
- **门槛导致延误**：常因无法自主完成分析而延误工作。

### 1.2 产品定位（一句话）

**一款"零代码"的对话式卫星遥感分析 Web 应用**：用户在浏览器用一句中文描述需求，系统自动完成「意图解析 → 代码生成 → 沙箱执行 → 自动调试 → 地图与图表可视化」的完整链路。

### 1.3 产品愿景

把专业遥感分析能力"平民化"——让不懂 GEE 编程的环保、农业、科研一线工作者，也能独立完成常见遥感分析任务。

### 1.4 产品价值

| 维度 | 价值 |
|---|---|
| 业务价值 | 零代码完成常见遥感分析，代码与结果透明可查 |
| 技术价值 | 实践「意图理解—代码生成—沙箱执行—错误自修复—可视化」智能体完整链路 |
| 社会价值 | 降低遥感/GIS 技术门槛，赋能环保、农业、科研一线，助力生态保护、精准农业与防灾减灾 |

## 2. 竞品分析与借鉴（重点章节）

### 2.1 参考产品：Earth Agent

**Earth Agent** 是一个 "Cursor 式的 Google Earth Engine AI 代理"，以 **Chrome 扩展**形态寄生在 GEE Code Editor 里，也可作为 **MCP Server** 供 Claude Code / Cursor / Zed 等 AI 编辑器调用。其核心能力：

- 聊天界面完成 GEE 辅助：写代码、跑代码、调试、解释地图、管理环境；
- **了解 GEE 数据目录与社区数据集**（geeDocs 知识检索）；
- **了解 GEE API**；
- 规划与推理（复杂任务自动拆多步）；
- 环境管理工具（重置地图/控制台、清空代码）；
- 完整的代理测试框架（自动化测试能力）；
- **Custom Instructions**（自定义指令，类似 AGENTS.md，对齐科学/政策目标）；
- **Agent Profiles**（自定义代理画像：如 "严格编码者 / 导师 / 分析师"）；
- **MCP Server 支持**（在 AI 编辑器里直接调用其工具）。

### 2.2 两个核心设计模式（最值得借鉴）

#### 模式一：Ask Mode vs Do Mode（只读 / 执行双模式）

Earth Agent 让用户显式选择代理的权限等级：

| 模式 | 能力 | 适用场景 |
|---|---|---|
| **Ask Mode（只读）🔍** | 读代码、查文档、截图、读控制台/地图状态；**不能**改代码/执行/清空环境 | 学习、理解代码、探索数据集、获取解释 |
| **Do Mode（执行）⚡** | 拥有 Ask 全部能力 + 写/改代码 + 执行 + 清空环境 + 端到端流程 | 建脚本、调试、自动化分析、多步任务 |

**借鉴价值**：降低"误执行"成本，让用户先理解再动手，符合非专业用户的心智模型。

#### 模式二：Custom Instructions（自定义指令）

类似软件工程的 `AGENTS.md` / `CLAUDE.md`，让用户给代理设定"标准作业流程"，对齐科研或政策目标：

- **科学严谨性**：如"Sentinel-2 云掩膜一律使用 Cloud Score+ 数据集"；
- **政策与表达**：如"所有解释写成适合决策者的政策简报，避免术语"；
- **方法论标准化**：如"年度合成一律用中位数而非均值"；
- **编码约定**：如"GEE 里优先用函数式 `map()` 而非客户端循环"。

**借鉴价值**：让同一个工具能适配不同学科/机构的规范，显著提升结果的专业可用性。

### 2.4 差异化定位（我们 vs Earth Agent）

| 维度 | Earth Agent | 本项目 |
|---|---|---|
| 产品形态 | Chrome 扩展（寄生 GEE Code Editor）/ MCP | **独立 WebApp**（B/S 架构） |
| 目标用户 | GEE 用户、开发者 | **零代码 / 非遥感专业用户** |
| 使用门槛 | 需 GEE 账号 + 打开 Code Editor | **无需 GEE 账号**（离线兜底可演示） |
| 语言 | 英文为主 | **中文自然语言** |
| 计算底座 | 直接操纵 GEE Code Editor | **可插拔执行后端**（真实 GEE / 离线样例） |
| 部署 | 浏览器扩展 | 本地部署 + cpolar 对外可访问 |

> **结论**：本项目不是 Earth Agent 的复刻，而是将其"聊天式 AI 代理"理念迁移到"面向零代码用户的独立 WebApp"，并通过**可插拔执行后端**解决国内 GEE 网络可达性问题。

## 3. 目标用户与画像

### 3.1 目标用户

- **生态与环保监测工程师**：需要定期做植被/水体/变化监测；
- **农业分析师**：需要作物长势、NDVI 分析；
- **科研人员**（生态学、地理学等）：有分析需求但不擅长 GEE 编程；
- 概括：**有明确遥感分析需求、但不具备 GEE 编程能力的零代码 / 低代码用户**。

### 3.2 用户画像

| 画像 | 特征 | 典型需求 | 痛点 |
|---|---|---|---|
| 环保监测工程师小李 | 环保局基层，会看地图不懂编程 | 每月监测太湖蓝藻/水体变化 | 依赖外包 GIS 人员，周期长 |
| 农学研究员王老师 | 懂作物，不会写代码 | 评估某区域作物长势 | 数据获取与分析门槛高 |
| 生态学研究生小陈 | 会一点 Python，不熟 GEE | 论文需要 NDVI 时间序列 | 调 GEE 代码耗时，反复试错 |

## 5. 功能需求

> 标注说明：✅ 已实现（当前代码具备）；🔶 建议新增（借鉴 Earth Agent，供后续迭代）。

### 5.1 对话式需求解析（✅）

- **功能描述**：用户输入中文自然语言，系统解析出任务类型、区域、时间、云量阈值等结构化参数；缺关键参数时返回澄清问题，支持多轮澄清。
- **交互**：对话气泡流；参数齐全自动触发分析。
- **降级**：无 LLM key 时用关键词规则兜底。
- **接口**：`POST /api/parse`（入参 `{text, partial}`，返回 `{fields, missing, question, complete, summary}`）。

### 5.2 代码生成（✅）

- **功能描述**：大模型（DeepSeek）生成 GEE Python 分析代码；结合任务模板。
- **降级**：无 key 时生成内置模板代码。
- **四类模板**：NDVI 植被指数、水体提取、地表分类、时序变化检测。

### 5.3 沙箱执行（✅ 离线 / 🔶 真实 GEE）

- **功能描述**：在受控后端执行生成代码，解析输出影像图层与统计结果。
- **可插拔后端**：`OfflineBackend`（内置样例数据，无 GEE 也可演示）/ `GEEBackend`（真实调用 Earth Engine，待服务账号凭据）。
- **安全要求**（任务书 3.3）：资源限额、超时控制、网络白名单。

### 5.4 自动调试（✅）

- **功能描述**：执行失败时读错误日志 → 分类（鉴权/参数/区域/算子用法等）→ 修复代码 → 重试（上限可配置）；鉴权类错误不重试；多次失败给人工建议。
- **编排**：LangGraph 状态机「生成 → 执行 → 调试」循环。

### 5.5 可视化与报告（✅）

- **地图**：Leaflet 渲染图层（GeoJSON / Tile）。
- **图表**：ECharts 渲染统计图（折线/柱状/饼图）。
- **报告导出**：Markdown 报告下载（含参数、代码、图层、图表、日志、AI 免责声明）。

### 5.6 任务与用户管理（✅ 历史/区域 / 🔶 登录）

- **历史任务**：`GET /api/tasks`，前端列表 + 点击回看。
- **常用区域**：内置 13 个区域坐标库 + 自定义增删（sqlite 持久化）。
- **注册登录**：✅ 已实现。PBKDF2-HMAC-SHA256 加盐哈希、服务端会话表（可即时吊销）、
  全接口鉴权、登录失败 5 次锁定 60 秒、支持修改密码；可用 `.env` 预置管理员消除首注册竞态。

### 5.7 借鉴新增：咨询/执行双模式（🔶）

- **功能描述**：对话区提供「咨询模式 / 执行模式」切换。
  - 咨询模式：只生成代码 + 讲解，不落库、不执行；
  - 执行模式：走完整链路。
- **价值**：让非专业用户先理解再动手，降低误执行成本。

### 5.8 借鉴新增：分析偏好设置（Custom Instructions）（🔶）

- **功能描述**：用户可设置全局科学规范 / 表达风格 / 编码约定，注入代码生成与结果解释的系统提示词。
- **示例**："云掩膜一律用 Cloud Score+"；"解释写成政策简报"。

### 5.9 借鉴新增：助手画像（Agent Profiles）（🔶）

- **功能描述**：内置/自定义助手画像（严格编码者 / 导师 / 分析师），各有独立 system prompt 与工具权限，可切换。

### 5.10 借鉴新增：RAG 数据集知识库（🔶，语料文档已建）

- **功能描述**：GEE 数据集清单 + API 用法 + 提示词模板库，供代码生成时检索，提升生成代码的正确率（对齐任务书 5.2 "RAG 语料库"）。
- **详见**：《RAG语料库.md》。

### 5.11 借鉴新增：示例 prompt 快捷入口（🔶）

- **功能描述**：对话区提供示例 prompt（如"帮我计算加利福尼亚的 NDVI"），一键填充，降低上手门槛。

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| **性能** | 典型任务（NDVI/水体）端到端 ≤60 秒（不含 GEE 云端排队）；意图解析秒级 |
| **安全** | GEE 凭据仅存服务端并加密，页面不明文；HTTPS；沙箱资源限额/超时/白名单 |
| **合规** | AI 生成内容按《互联网信息服务深度合成管理规定》显著标识；不构成权威结论 |
| **兼容性** | 主流浏览器（Chrome/Firefox/Safari/Edge）最新两个版本 |
| **可用性** | 无 LLM key、无 GEE 账号也能跑通全链路（降级兜底） |
| **数据隐私** | 用户区域/任务描述敏感，加密存储；本地化部署；不用于服务以外用途 |

| 一次执行成功率 | ≥70% | 常见任务首次执行即成功占比 | 测试任务集（🔶 待建） |

| 典型任务耗时 | ≤60 秒 | 提交到结果返回时长（不含 GEE 排队） | 日志计时 |
