四、关键设计决策

4.1 可插拔执行后端

GEE 账号与国内网络可达性是外部不确定因素，因此把执行抽象为 ExecutionBackend 接口，提供两个实现。演示与开发可选择离线后端，保证「无凭据也能跑通全流程」；凭据就绪后切 EXECUTION_BACKEND=gee 即走真实链路，上层编排与前端无需改动。

4.2 单端口同源托管

前端构建产物由 FastAPI 直接托管，浏览器与服务同源，因此生产环境不需要 CORS。这既简化部署（一个进程对外），也消除了跨域带来的 Cookie 策略约束。

4.3 沙箱的存在理由

生成代码由大模型按用户输入产出，属于**不可信输入**。沙箱在子进程里执行它，并封禁网络访问、子进程创建、以及敏感文件读取（.env / *.db / 凭据目录）。加固点位于工具链校验之后、用户代码执行之前 —— 顺序错了会把工具链自己的配置读取一起封死。

4.4 数据隔离

所有业务表带 user_id，语义统一为 0 = 无主/全局默认、>0 = 属于该用户。越权访问返回 404 而非 403 —— 403 会暴露"该 ID 确实存在"，把主键空间变成可探测的泄漏面。

4.5 日期基准唯一来源

默认分析区间集中在 app/daterange.py，口径为「最近一个完整自然年」。历史上该基准曾散落 8 处并整体过期一年以上，因此新增了一条回归守卫，断言"值随当天推算"而非"值等于某常量"。
