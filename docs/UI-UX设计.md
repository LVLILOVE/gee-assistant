|---|---|

---

## 1. 设计目标与原则

| 原则 | 说明 |
|---|---|
| **零门槛** | 首屏即对话，用户无需理解参数即可上手 |
| **渐进披露** | 高级参数折叠，默认只露对话 + 结果 |
| **透明可查** | 代码、日志、执行状态全程可见，建立信任 |
| **状态可感知** | 后端状态、执行进度、参数就绪度用标签清晰呈现 |
| **先理解后执行** | 🔶 借鉴 Earth Agent：默认"咨询"、确认后再"执行" |

## 4. 交互流程

### 4.1 对话式分析主流程（已实现）

```
用户输入自然语言
   │
   ▼
POST /api/parse 意图解析
   │
   ├─ 参数齐全 ──────────────► 自动提交任务 ─► 轮询 /api/tasks/{id}
   │                                              │
   └─ 缺参数 ──► 返回澄清问题 ─► 用户续答 ─► 合并 partial 再解析
                                                  │
                                   ┌──────────────┴──────────────┐
                                   ▼                             ▼
                              执行中(Spin)                    成功/失败
                                   │                             │
                                   ▼                             ▼
                          地图 + 图表 + 代码                  错误卡片 + 日志
```

### 4.2 多轮澄清（已实现）

| 步骤 | 用户输入 | 系统响应 |
|---|---|---|
| 1 | "我想看洞庭湖的情况" | 识别区域=洞庭湖，追问"想做哪类分析？" |
| 2 | "我要做水体提取" | 合并已确认的洞庭湖 → 水体提取，直接执行 |

### 4.3 咨询/执行双模式（🔶 借鉴 Earth Agent Ask/Do）

| 模式 | 行为 |
|---|---|
| 咨询模式 | 只返回"代码 + 讲解"，不落库、不执行、不渲染地图 |
| 执行模式 | 走完整「生成→执行→调试→可视化」链路 |

## 5. 组件规范

### 5.1 状态标签（Tag）

| 状态 | 颜色 | 文案 |
|---|---|---|
| pending | default | 排队中 |
| running | processing | 执行中 |
| loading | processing | 加载中 |
| succeeded | success | 成功 |
| failed | error | 失败 |
| 后端在线/离线 | green / red | 后端 在线/离线 |
| LLM 已配置/未配置 | blue / orange | LLM 已配置 / 未配置(兜底) |

### 5.2 地图组件（Leaflet）

- 底图：OpenStreetMap tile；
- 图层：GeoJSON 叠加渲染，按 legend 配色；
- 交互：自动 `fitBounds` 定位到分析区域。

### 5.3 图表组件（ECharts）

- 折线图（line）：时序趋势（如逐月 NDVI 均值）；
- 柱状图（bar）：分类对比；
- 饼图（pie）：占比（如地表分类面积占比）。

### 5.4 视觉风格

**自然主题（2026-09-23 落地）**。原方案用 Ant Design 默认主题（主色蓝），
与"遥感 / 生态 / 环境监测"的产品语境不匹配，故整体换肤为森林绿 + 大地色。

- **组件库**：Ant Design 5，经 `ConfigProvider` 注入定制令牌。
  **不用 CSS 覆盖 `.ant-*` 类** —— antd 会从 `colorPrimary` 派生 hover / active /
  边框 / 聚焦环等几十个色阶，只覆盖最显眼那一层会留下"悬停还是蓝色"的割裂感。
- **令牌单一来源**：`frontend/src/theme.js` 导出 `palette` / `chartPalette` / `antdTheme`；
  `style.css` 的 `:root` 提供同名 CSS 变量供自有 DOM 与 Leaflet 复用。
  换肤 = 改这两个文件，不必满仓库找色值。
- **主色**：深林绿 `#2d6a4f`（moss600）—— 与植被/水体这类分析对象天然关联。
- **页面底色**：微暖米 `#f6f5f0`，不用冷灰 —— 遥感影像本身偏冷（蓝绿灰），
  背景再冷会整体发青。
- **状态色降饱和**：原 `#52c41a` / `#ff4d4f` 在绿色主色旁互相打架，
  改为 `#3f7d44` / `#a33b2c`。
- **图表色序**：`chartPalette` 硬编码十六进制（ECharts 是 canvas，读不到 CSS 变量），
  按"相邻两色在灰度下也能分辨"排布，兼顾色觉障碍用户。
- **地图图例配色**：分区分类与植被指数图例**只调饱和度、不改色相顺序** ——
  NDVI 的 红→黄→绿 是行业与用户的既有认知，为"配色统一"改掉会误导判读。
- **对话气泡**：用户右侧主色、助手左侧苔绿浅底。
- **常用区域标签**：绿色系可点击 Tag；反引号 `var()` 令牌化，无硬编码色值。

**无障碍**（硬要求，见 `tools/test_a11y_contrast.py` / `test_a11y_kbd.py`）：

- 全部正文文字对比度 **实测**通过 WCAG AA，最紧一处 4.91:1（结论免责声明），
  最好 13.94:1（历史任务标题）。**数值必须来自浏览器实测** —— 手算会偏乐观，
  本项目 `ink-500` 初版手算 4.6:1、实测仅 4.24:1。
- 键盘可达：9 个可交互元素均可 Tab 到达；焦点环统一补 `:focus-visible`
  （antd 默认给 Tag / Segmented 设了 `outline:none`，键盘用户会"看不见自己在哪"）。
- `prefers-reduced-motion` 已尊重；`@media (hover: none)` 关闭触屏粘滞 hover。
- 触控目标：移动端标签/分段控件提到 ≥24px（44px 理想值会占掉密集顶栏半屏，
  已在 CSS 注释中说明取舍）。

**验证方式**：改过 UI / 配色后跑 `bash tools/regress_all.sh --with-a11y`
（需 `:8010` 在跑）。焦点可见性用**截图逐像素比对**判定，不读 `outline` 属性 ——
antd 的按钮焦点环是 `box-shadow` 画的，`outline` 天生为 `none`，按属性判会误判。
