| 项目 | 内容 |
|---|---|
| 文档版本 | V1.1 |
| 更新日期 | 2026-09-15 |
| 技术栈 | React + Ant Design + Leaflet + ECharts |
| 借鉴参考 | [Earth Agent](https://github.com/wybert/earth-agent-chrome-ext)（Ask/Do 模式、示例 prompt 等） |

---

## 1. 设计目标与原则

| 原则 | 说明 |
|---|---|
| **零门槛** | 首屏即对话，用户无需理解参数即可上手 |
| **渐进披露** | 高级参数折叠，默认只露对话 + 结果 |
| **透明可查** | 代码、日志、执行状态全程可见，建立信任 |
| **状态可感知** | 后端状态、执行进度、参数就绪度用标签清晰呈现 |
| **先理解后执行** | 🔶 借鉴 Earth Agent：默认"咨询"、确认后再"执行" |

## 4. 交互流程

### 4.1 对话式分析主流程（已实现）

```
用户输入自然语言
   │
   ▼
POST /api/parse 意图解析
   │
   ├─ 参数齐全 ──────────────► 自动提交任务 ─► 轮询 /api/tasks/{id}
   │                                              │
   └─ 缺参数 ──► 返回澄清问题 ─► 用户续答 ─► 合并 partial 再解析
                                                  │
                                   ┌──────────────┴──────────────┐
                                   ▼                             ▼
                              执行中(Spin)                    成功/失败
                                   │                             │
                                   ▼                             ▼
                          地图 + 图表 + 代码                  错误卡片 + 日志
```

### 4.2 多轮澄清（已实现）

| 步骤 | 用户输入 | 系统响应 |
|---|---|---|
| 1 | "我想看洞庭湖的情况" | 识别区域=洞庭湖，追问"想做哪类分析？" |
| 2 | "我要做水体提取" | 合并已确认的洞庭湖 → 水体提取，直接执行 |

### 4.3 咨询/执行双模式（🔶 借鉴 Earth Agent Ask/Do）

| 模式 | 行为 |
|---|---|
| 咨询模式 | 只返回"代码 + 讲解"，不落库、不执行、不渲染地图 |
| 执行模式 | 走完整「生成→执行→调试→可视化」链路 |

## 5. 组件规范

### 5.1 状态标签（Tag）

| 状态 | 颜色 | 文案 |
|---|---|---|
| pending | default | 排队中 |
| running | processing | 执行中 |
| loading | processing | 加载中 |
| succeeded | success | 成功 |
| failed | error | 失败 |
| 后端在线/离线 | green / red | 后端 在线/离线 |
| LLM 已配置/未配置 | blue / orange | LLM 已配置 / 未配置(兜底) |

### 5.2 地图组件（Leaflet）

- 底图：OpenStreetMap tile；
- 图层：GeoJSON 叠加渲染，按 legend 配色；
- 交互：自动 `fitBounds` 定位到分析区域。

### 5.3 图表组件（ECharts）

- 折线图（line）：时序趋势（如逐月 NDVI 均值）；
- 柱状图（bar）：分类对比；
- 饼图（pie）：占比（如地表分类面积占比）。

### 5.4 视觉风格

- 组件库：Ant Design 默认主题；
- 对话气泡：用户右侧主色、助手左侧浅灰；
- 常用区域标签：蓝色可点击 Tag。
