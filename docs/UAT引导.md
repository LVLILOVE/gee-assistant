# UAT 引导（真实用户验收测试）

> 本文件解决项目**最大的产品风险**：至今 0 份真实用户反馈。
> 你只需要把下面「给测试者的话」原样发出去，然后看结果。

---

## 一、为什么要做（30 秒看懂）

系统已经跑通了 66 条任务，但**全部是开发者自己跑的**。
开发者自己测，永远测不出这类问题：

- 不知道要输入什么（功能没有自我介绍）
- 等 50 秒没进度条，以为卡死了就关掉
- 看不懂"NDVI 均值 0.32"是什么意思
- 结论对不对，无法判断

**这几类问题只有真实用户能暴露。** 而且它们**不会**出现在任何自动化测试里。

---

## 二、发什么给测试者（直接复制）

> 帮个忙，测一下我做的遥感分析工具，大概 5 分钟。
>
> **地址**：（把当前公网地址填这里 —— 见第四节怎么拿）
>
> **步骤：**
> 1. 打开链接 → 点「注册」→ 用户名密码随便设（如 `test01` / `test01pass`）
> 2. 在对话框里**直接用中文说一句话**，例如：
>    - `帮我分析太湖流域 2024 年的 NDVI`
>    - `提取鄱阳湖 2024 年夏季的水体范围`
>    - `对比深圳市 2024 年和 2023 年的植被变化`
> 3. 等 30~90 秒（真的在调 Google Earth Engine 算卫星影像，不是在假加载）
> 4. 看到地图和图表后，**点一下 👍 或 👎**，顺便可以留一句话
> 5. **如果它挂了或者你看不懂结果，请直接告诉我哪一步、屏幕上是什么** ——
>    报错比成功更有价值
>
> 请一定说真话，觉得难用/看不懂就直接说，我在收集问题。

**要点（别改）**：
- 说「真的在调 GEE 算卫星影像」→ 否则等 50 秒会被当成卡死
- 明确要 👍/👎 → 这是本项目的核心验证动作
- 明确鼓励报错 → 否则测试者遇到卡住会直接关掉，你什么都收不到

## 三、收什么、怎么看

测试者跑完后，你（或我）执行：

```bash
cd backend
env -u PYTHONPATH ./.venv/Scripts/python.exe -c "
import sqlite3, json, time
from app.crypto import decrypt_field
c = sqlite3.connect('data/app.db'); c.row_factory = sqlite3.Row
for r in c.execute('''select t.task_id, t.user_id, t.task_type, t.region, t.status,
                             t.attempts, t.created_at, t.feedback, t.feedback_note
                      from tasks t order by t.created_at desc limit 20'''):
    d = dict(r)
    print('#%s u=%s %-16s %-9s att=%s %s 反馈=%s' % (
        d['task_id'], d['user_id'], d['task_type'], d['status'], d['attempts'],
        time.strftime('%m-%d %H:%M', time.localtime(d['created_at'])), d['feedback']))
    print('   区域:', decrypt_field(d['region']))
    if d['feedback_note']:
        print('   留言:', decrypt_field(d['feedback_note']))
"
```

**看三样东西**：
1. **有没有 `user_id != 4` 的任务** → 真实用户真的跑通了
2. **`feedback` 列有没有值** → 验证动作发生了
3. **`feedback_note` 写了什么** → 这是**唯一无法用技术手段获取**的信息

**判定标准（先说好，避免自我安慰）**：
- 有 ≥3 个真实用户**且** ≥3 条真实任务**且** ≥3 条反馈 → UAT 才算有数据
- 只有 1 个用户跑 1 条 → 仍算「样本不足」，**不能写进答辩材料当结论**

## 四、公开前的检查清单（每次都要做）

```bash
# 1) 后端在跑吗（必须看到 LISTENING）
netstat -ano | grep ":8010" | head -3

# 2) 健康检查（必须 --noproxy，否则代理返 502 会让你误判服务挂了）
curl -s --noproxy '*' http://127.0.0.1:8010/health

# 3) cpolar 在跑吗 / 当前地址是什么
tasklist | grep -i cpolar
curl -s --noproxy '*' http://127.0.0.1:4040/http/in | grep -oE 'https?://[a-z0-9]+\.r3[0-9]\.cpolar\.[a-z]+'

# 4) 公网地址真的通吗（把 <URL> 换成上一步拿到的）
curl -s -o /dev/null -w '%{http_code}\n' -m 15 <URL>/health
```

**⚠️ 发链接前必须验第 4 步。**
cpolar 免费版会自己死掉且不报警 —— 直接把死链接发给评审/测试者，
对方看到的是「无法访问此网站」，你会以为是产品坏了。

## 六、做完之后

把结果给我，我会：
1. 按反馈**逐条**对照代码定位（每条反馈都要能指到具体文件/行为）
2. 区分「真缺陷」与「预期行为」—— 不把"用户不理解"当成"功能错了"
3. 把有价值的反馈**写进评估报告的真实用户章节**（这是当前报告的空白页）
4. 对确认的缺陷按 P0/P1/P2 排期修复

**不要**把 1 条反馈写成「用户满意度良好」。
项目已有教训：**弱信号漂亮 ≠ 产品达标**。
`feedback_summary()` 在无评分时返回 `None` 而不是 `0.0`，就是这个原则的代码化。
